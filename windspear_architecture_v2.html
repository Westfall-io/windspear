System Overview

Purpose: Windspear is an automated webhook-driven processing system that extracts, parses, and validates SysML v2 models from Git repositories, storing requirements, verifications, and actions for downstream CI/CD pipelines.

Key Capabilities

  • Webhook-Driven Processing: Triggered by Git push events via Argo Events
  • SysML v2 Model Extraction: Parses Jupyter notebooks containing SysML models
  • Requirements Management: Extracts and stores requirement definitions
  • Verification Tracking: Links verification cases to requirements
  • Action Orchestration: Identifies and manages executable actions with dependencies
  • Database Persistence: Stores all artifacts in PostgreSQL for traceability
  • Downstream Integration: Notifies Windstorm for further processing

Technology Stack

Core Technologies

  • Python 3.11
  • SysML v2 Jupyter Kernel (v0.34.0)
  • Papermill (Notebook Execution)

Functional Architecture

Processing Pipeline Flow

1. Webhook Reception

Argo Events receives Git push webhook with ref, commit, and repository path

↓
2. Pod Initialization

Sensor creates Windspear Pod with environment variables and webhook payload parameters

↓
3. Repository Checkout

GitRepositoryInterface clones repository, switches to branch, collects commit metadata, checks out specific commit

↓
4. Commit Registration

DatabaseInterface inserts/updates commit record with metadata and marks as unprocessed

↓
5. Model Discovery

NotebookProcessor searches for .ipynb files with SysML/sos kernels, extracts SysML code cells

↓
6. Model Execution

Papermill executes temporary notebook with SysML kernel, exports element JSON from outputs

↓
7. Element Parsing

ModelParser decodes base64 JSON, identifies RequirementUsage, VerificationCaseDefinition, ActionUsage elements

↓
8. Artifact Persistence

DatabaseInterface stores models, elements, requirements, verifications, actions with relationships

↓
9. Verification Analysis

System validates actions have Harbor container URIs and artifact storage locations

↓
10. Completion Notification

Commit marked as processed, Windstorm webhook notified with branch reference

Action Processing Logic

Action Validation Criteria

An action is considered valid for DigitalForge execution if:

  • ✅ Has a Harbor container image URI specified
  • ✅ Has an artifacts storage location (e.g., MinIO URI)
  • ✅ All required variables are defined with units
  • ✅ Dependencies are resolved (if present)

Error Handling

Retry Mechanisms

  • SysML Kernel Start: Up to 5 retry attempts with exponential backoff
  • Database Connections: Connection pooling with automatic reconnection
  • Git Operations: Credential injection for authenticated access

Deployment Workflow

  1. Developer pushes to Git: Commit triggers webhook to Argo Events
  2. Webhook received: EventSource captures POST request with payload
  3. Sensor triggers: Creates ephemeral Windspear Pod with webhook parameters
  4. Pod starts: Pulls Docker image, initializes Python environment
  5. Processing begins: main.py orchestrates entire pipeline
  6. Repository cloned: Git operations via GitPython
  7. Models executed: SysML kernel processes notebooks
  8. Data persisted: PostgreSQL stores all artifacts
  9. Notification sent: Windstorm receives completion webhook
  10. Pod terminates: restartPolicy: Never ensures cleanup

Scaling Considerations

Performance Notes

  • Ephemeral Pods: Each webhook creates a new pod - no state preservation
  • Concurrent Processing: Multiple webhooks create multiple pods in parallel
  • Database Connection Pooling: SQLAlchemy manages connection lifecycle
  • SysML Kernel Startup: 5-retry mechanism handles kernel initialization failures
  • Git Clone Operations: Fresh clone for each execution ensures consistency
